# ADR 0001：自建预设的真相放在用户补丁层的托管 insert 块

- 状态：已接受
- 日期：2026-11-10

## 背景

DSH 有三种途径让一个新预设出现：

1. **运行期注册**：插件在 `init` 中调用 `agentPresets.register(definition)`。注册只存在于内存（registry 的 `PresetTree.commit` 为空，官方代码注释说明只有 profile 配置编辑器会持久化定义），进程重启后消失；插件被禁用或卸载时预设随之消失。
2. **安装 bundle**：写一个声明预设的 bundle，用 `plugin_manager install_bundle` 装入 profile。这是官方文档推荐的新增路径，但每次保存都要生成包目录、改依赖清单、跑包管理器，作为交互式编辑器太慢。
3. **用户补丁层**：profile 的 `cordis.patch.yml` 本来就是用户层，官方 README 明说这一层可以覆盖配置、禁用行、插入新行。新增行必须写在 `- insert:` 里。

## 决策

自建预设的唯一真相放在 profile 用户补丁层的一个托管 `- insert:` 块里，块首尾有固定注释标记；插件只替换标记之间的内容。写入后通过 HMR 热应用。

## 理由

- 预设与内置预设同为 `@deepseek-ai/dsh-agent-preset` 声明行，进同一 registry、同一选择器，不需要官方 UI 做任何适配。
- 重启后仍在；插件被禁用或卸载也不影响预设存在。
- 保存是纯文本写入，交互快；没有包管理器参与。
- 用户可见、可版本管理、可手工救援。

## 代价

- 插件必须写宿主 profile 文件。缓解：只动标记块、原子写、失败可见、块外字节不变。
- 没有官方「插入行」的插件 API，属于按用户层文档行事；升级 DSH 时需要回归验证补丁语义。
- 无 HMR 时保存后需重启，界面必须如实告知。

## 备选

- 运行期注册：快，但预设成为插件运行期副产品，违反「与其它预设无差别」的要求。
- 每预设一个 bundle：最官方，但保存链路太重，且会让 profile 依赖清单膨胀。
