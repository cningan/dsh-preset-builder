# ADR 0003：平台条件行的开关只读

- 状态：已接受
- 日期：2026-11-10

## 背景

官方预设用 `disabled: !!js process.platform === 'win32'` 这类表达式让一行只在部分平台挂载。这类行同时承载两种信息：是否启用，以及在什么条件下启用。如果界面允许「禁用」，最直接的实现是把整行写成 `disabled: true`，那会永久丢掉平台条件；如果允许「启用」，又要把表达式替换成 `false`，同样是信息损失。

## 决策

- `disabled` 为 `!!js` 表达式的行，其启用状态在界面上只读。
- 界面解析表达式文本，显示平台徽标（如「仅 Windows」「仅 macOS/Linux」）；解析不出时显示「条件启用」，不猜测平台。
- 普通 `disabled: true/false` 的行仍可正常启用、禁用、移出。

## 理由

- 保存语义单一：只读行在编辑过程中不会被意外改写。
- 用户建立预设时真正要决定的是「收不收这一行」；收进来后平台条件交给表达式本身。
- 解析失败时如实标注，比给出错误结论更安全。

## 代价

- 用户不能在界面里强制启用某个平台变体；需要时得移出后手工加一行或改 YAML。
- 平台标签依赖表达式文本的常见形态，非标准写法只能显示为通用条件。

## 备选

- 三态开关（跟随条件 / 强制禁用 / 强制启用）：表达力最强，但会改写表达式，且三态的语义解释成本高，用户已明确选择只读。
