# ADR 0004 — 自定义预设一视同仁：接管、锁定与墓碑

- 状态：已采纳
- 日期：2026-11-10

## 背景

首版把预设分成「内置 / 本插件托管 / 其它来源（外部）」三类，外部预设只读、不能删除。实际使用暴露出两个问题：

1. 删除只改页面草稿，用户必须再点保存才落库；在官方预设页看，预设仍然存在，像删除失效。
2. 用户的心智模型只有两类：官方不可动，其它都该能管。把「外部」单列成第三类、只读展示，既增加认知负担，也让坏掉的外部预设无法清理。

## 决策

1. **只有官方四个标准 id（`minimal`、`standard`、`ptc`、`cordis`）永久只读**；其余 registry 预设全部归入「自定义」。
2. **托管块是唯一管理面**，可含三种条目：
   - `- insert:`：本插件创建的声明，loader 行 id 为 `preset-studio-<id>`；
   - 覆盖条目：接管外部声明，按**原 loader 行 id** 重写 `config`；
   - 墓碑：`- id: <原行 id>` + `disabled: true`，压制被删除的声明，避免 bundle 升级后复活。
3. **接管 = 覆盖原行**。通过 `ctx.loader.entries()` 找到 `name == '@deepseek-ai/dsh-agent-preset'` 且 `config.id` 匹配的行，写同 id 的覆盖条目；不新增同 id 声明，因此不会触发「Duplicate agent preset」。运行时注册、没有 loader 行的预设无法接管。
4. **锁定**：任意自定义预设可锁定；名单存在块内 `# locks: <id, …>` 注释行。锁定期间本插件不保存、不删除、不接管该预设。
5. **删除即时生效**：`POST /presets/delete` 直接改块并热应用；创建条目直接移除，接管/外部声明留下墓碑。bundle 卸载后遗留的墓碑在下次写入时按现存声明行自动清理。
6. 保存仍是显式的批量草稿，但只处理已托管预设；锁定预设的载荷被服务端忽略。

## 影响

- 删除与锁定不再依赖页面上的「保存」，与用户预期一致；坏预设可以立即清掉。
- 托管块从「只有 insert」升级为「insert + 覆盖 + 墓碑 + 锁定注释」，块解析与生成、单测都要覆盖四种条目。
- 外部预设被接管后，其声明归属当前 profile：升级原 bundle 不会自动改变它；卸载本插件会连同托管块一起移除，此时原 bundle 的声明会重新出现。
- 全部条目被删除且没有锁定/墓碑时，托管块整体消失，profile 恢复原样。
- 墓碑只压制声明行，不删除其它插件的文件；它是对补丁层的一次覆盖，属于可逆的文本操作。
