# ADR 0006：托管模块按内容定位，不写末尾注释

- 状态：已接受
- 日期：2026-11-22

## 背景

0.6.x/0.7.x 用首行与末行两条注释圈定托管块。YAML 里文件末尾的注释是**尾部注释**，序列化时永远排在所有条目之后；而 DSH 官方配置编辑器新增配置行用的是 `document.add()`，把节点追加到序列 items 末尾。两者叠加，新行必然落在两条注释之间——也就是模块内部。下一次插件保存整段重写标记区间时，这行被静默删除（上游 issue #1，真实丢失过 `llm-pi-ai` 提供方定义）。

## 决策

- **不写末尾注释**。模块的最后一条是真实 YAML 条目，追加操作落在它之后。
- **模块边界由条目内容判定**（`scanModule()`）：只有本插件可能写出的完整形状算自有内容；首行注释只做说明，丢失不影响管理。
- 模块区间内混入的外来条目在保存时移到模块之前；区间外的外来行保持原位。
- 旧格式的末尾注释在下次保存时删除。

## 理由

- 注释不是容器，用它当边界等于把 YAML 的尾部注释语义当成契约，必然被"追加到末尾"的操作穿透。
- 内容判定与追加位置无关：追加行落在最后一条之后，天然在模块外，不需要锚点、不需要特殊行。
- 首行注释不参与定位后，注释丢失/被改不再导致"预设变成外部声明"或"重复写行 id"。

## 代价

- 覆盖行与墓碑和手写声明无法从内容区分；误判为自有条目时只影响管理范围，不丢内容（重写保持 id + disabled/config）。
- 模块的自有条目分散在文件多处时，区间会被拉长，中间内容被当外来上移（极端情况，可接受）。

## 备选

- 在末尾加非注释锚点（如 `- insert: []`）：引入额外 Loader 行，用户可见且语义怪异，拒绝。
- 拆到独立文件、patch 只留引用行：Loader 只读 patch，外部文件只能靠运行期注册或 `!!js` 读取，脆弱且违反 ADR 0001，拒绝。
